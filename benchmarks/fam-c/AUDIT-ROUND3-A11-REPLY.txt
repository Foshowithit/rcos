P1 — request evidence is tamper-evident under the harness TCB, not “unfalsifiable”

On your third question: persisting request bytes is the right move, but don't make the stronger claim that it is impossible for the same process to falsify what it sent.

The harness constructs blob, sends it, then after the response writes that blob to disk.

Your trust model therefore is:

frozen harness code = trusted
artifacts = tamper-evident against later mutation

not:

artifacts cryptographically prove what an actively malicious harness sent

No provider currently echoes the full request body hash back to you, so the latter is impossible from these receipts alone.

I'd tighten the implementation anyway:

construct blob
→ persist exact request bytes
→ hash persisted bytes
→ read/send those exact persisted bytes
→ receive response

Then the audited frozen program has a visibly single source of truth even for the send operation.

Still describe it as:

request bytes are mutation-evident and execution-bound under the frozen harness trust boundary.

That's scientifically defensible.

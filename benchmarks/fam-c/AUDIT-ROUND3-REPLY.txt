3. Request-body hashing is good, but “alter any explicit generation param → failure” is not yet truly proven

This is subtler.

You now hash the exact POST body, which is good. Identity stores the same hash.

But verify_identity_binding() compares:

identity.request_body_sha256
==
receipt.request_body_sha256

It does not reconstruct that hash from the recorded model/messages/generation parameters, nor does it compare identity.generation_params against an independently persisted request body.

So before the evidence chain is minted, an altered:

JSON
"generation_params": {"max_tokens": 123}

can still agree with the untouched body hash because there is no verifier proving those params generated that body hash.

Your comment says the complete params are bound; mechanically they aren't yet.

Best fix

Persist the exact POST body bytes:

call-<id>.request.json

or equivalent immutable artifact.

Then verify:

sha256(request bytes)
    == receipt.request_body_sha256

request.model
    == identity.model_requested

request generation fields
    == identity.generation_params

request messages[0].content hash
    == prompt/context hash

Chain its SHA too.

That will become especially useful in item #13 anyway.

Acceptance: mutate temperature/max_tokens/model/prompt in any one representation and the independent verifier fails.

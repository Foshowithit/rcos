The adapter turns a new record format into the engine's two inputs: (1) records.json — a JSON list of flat dicts, one per source record, using the raw source keys verbatim; (2) field_map.json — a JSON object with keys 'id', 'name', 'amount', 'tags' each mapped to either a string (the source key) or a list of candidate keys tried in order, plus optional 'tag_sep' (default ','). For CSV: read with csv.DictWriter/DictReader, dump rows to records.json, derive field_map from the header (e.g. {id:['OrderID','order_id'], name:'Item', amount:'Price', tags:'Labels', tag_sep:'|'}). For nested JSON: walk to the record array (e.g. payload['results'][0]['items']), flatten if nested keys are needed, and emit. Pass USD strings exactly as they appear in source — the engine handles '$', thousands commas, decimals, leading minus, and accounting parentheses. Adapter is responsible for any source-specific quirks (timezone, encoding, date parsing); engine does no other type coercion.

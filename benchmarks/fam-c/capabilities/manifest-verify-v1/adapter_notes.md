The adapter converts a NEW manifest+raw-files pair into the two JSON inputs the engine consumes. Steps: (1) Parse the native manifest format into field_map: { record_path: { field_name: { 'size': N?, 'sha256': 'hex'? } } }. For colon manifests split on ':', for JSON traverse nested layouts flattening dot-paths, for env-style (KEY=VAL or KEY VAL) split on first delimiter and treat keys as fields, using the record's overall path as the record_path key. (2) Parse raw files into records: { record_path: { field_name: raw_value } }, preserving original byte/str form so sha256 hashing in the engine matches. (3) Write both as JSON to disk and invoke: python3 engine.py <field_map.json> <records.json> <out.json>. The engine returns 0 on success; the adapter reads out.json to populate ok/bad/unverified for the solver.

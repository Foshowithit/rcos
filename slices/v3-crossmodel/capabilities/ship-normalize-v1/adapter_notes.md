The adapter is the only format-aware component. It must (1) detect the input format, (2) parse it into a 'flat string records dict' where scalar fields live at dot-notation paths as string values (e.g., {'ship_id': 'S-201', 'from': 'OSLO', 'to': 'SINGAPORE', 'weight_kg': '783.3'} for CSV; {'id': 'S-202', 'route.src': 'HAIFA', 'route.dst': 'SINGAPORE', 'mass_kg': '172.2'} for JSON), and (3) place the items line list as a JSON-serialized string at the path named by the chosen map's items.__list__ key (e.g., 'items_raw' for the CSV sku:qty section, 'contents' for the JSON contents array). Numeric values stay as strings in the records dict; the engine coerces. For new formats, write a new map describing the canonical-to-source path correspondence plus the items sub-key renames, and extend the adapter to produce the corresponding flat records dict.

# Slice 1: Portable Capability Reuse — PRE-REGISTRATION

Committed + pushed BEFORE any solver, capability, router-run, or result
exists. The public history must show this file predating all execution
artifacts — that ordering IS the methodology upgrade over Slice 0.

## Question under test

Does procedural knowledge persist in the capability ARTIFACT such that an
independent solver context — which never participated in acquiring it — can
retrieve, execute, and benefit from it on a held-out task?

## Task family: service-config normalization (NOT invoices)

Structural dimensions: format (INI vs JSON vs env-style KEY=VALUE), key
naming, nesting vs flat, missing optionals (defaults apply), junk entries,
value spellings (booleans as true/yes/1/on).

- **T1** (`c1-ini`): INI file `[service]` + `[limits]` sections.
- **T2** (`c2-json`): JSON, different keys, nested `network{}` block,
  missing `retries` (default 3), irrelevant `notes` + `tags`.
- **T3** (`c3-env`, HELD OUT): flat `KEY=VALUE` lines, yet another naming
  (`SVC_NAME`, `PORT`, `DEBUG`, `RETRY_COUNT`, `HOSTS` csv), `#` comments,
  junk lines. Generated by seed, unseen by builder roles.

Canonical schema: `{service: str, port: int, debug: bool, retries: int,
allowed_hosts: [str]}`. Defaults: `retries=3`, `allowed_hosts=[]`.
Booleans accept true/false/yes/no/1/0/on/off (case-insensitive).

## Capability-claim boundary

Reusable: canonical mapping + type coercion + defaults + validation
(port 1–65535, retries ≥ 0). Per-format parsing is composed adapter work,
logged as `composed`, never as the capability.

## Arms (all on held-out T3, fresh workdirs, mechanical grading)

1. **correct**: registry lookup → normalize-config capability → execute →
   output consumed by eval.
2. **forced-wrong**: registry FORCED to Slice-0 `normalize-invoice-v1`
   (plausible — both are "normalizers" — but wrong domain). Must execute
   and be MEASURED failing. Predicts: eval fail, proving benefit comes
   from specific knowledge, not any extra context.
3. **disabled**: registry off, fresh solve. Baseline cost/outcome reference.

Negative-rejection logging stays (router must also reject held-out
distractors), but the forced-execution arm is the new bar: selection
quality AND execution causality are measured separately.

## Role barriers (procedural; residual limitation declared)

A=author (this prereg, frozen+pushed first). B=builder (T1/T2 only, never
opens T3 fixtures). C=solver (T3 only at execution, capability + task
only). D=auditor (trace/receipt/hash verification against this file).
One operator executes all roles; barriers are enforced by commit ordering
(prereg predates runs in public history), sealed T3 hashes below, and
fresh workdirs. Model-family variation is VACUOUS here — all oracles are
deterministic stdlib with zero model calls, so there is no model to vary;
cross-model replication belongs to Fam-C model-node tasks, not this slice.

## Decision rule

Slice ships iff: prereg predates runs publicly → T1/T2 ship → promote →
arm 1 ships via executed+consumed capability → arm 2 FAILS as predicted
(wrong capability executes, eval rejects) → arm 3 measured → trace proves
all three. If arm 2 accidentally ships, the family is insufficiently
discriminating — redesign, do not reinterpret.
